# Mediator Pattern

The Mediator pattern reduces coupling between components by making them communicate through a central point. It promotes loose coupling by keeping objects from referring to each other explicitly.

## Real-World Analogy
Think of an air traffic control tower:
- Multiple planes in the air
- Planes don't communicate directly with each other
- All communication goes through the control tower
- Tower coordinates all flight paths and landings

## Problem It Solves
- Reduces coupling between components
- Centralizes control logic
- Simplifies object protocols
- Makes it easier to modify system behavior

## When to Use
- When components need to communicate but should stay loosely coupled
- When component interactions are complex or poorly defined
- When you want to reuse components in different contexts
